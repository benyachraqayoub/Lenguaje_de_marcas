Archivo 2: respuestas.txt (Tareas 1, 2 y 5 explicadas)
Texto explicativo 
=== TAREA 1: 7 ERRORES DETECTADOS ===
1. nombre: 'Gimnasio Olympia Valencia' -> La propiedad "nombre" no lleva comillas dobles y el valor usa comillas simples en lugar de comillas dobles.
2. "cuotaBase": 39,90 -> En JSON los decimales deben escribirse con punto (39.90), nunca con coma.
3. "aforoMaximo": "120" -> Error de tipo de dato: el aforo máximo es una cantidad entera (120) de tipo Number, no un texto ("120").
4. "abiertoFestivos": False -> Error de sintaxis: en JSON el booleano falso se escribe en minúsculas (false).
5. Falta la coma (,) para separar el primer objeto { "zona": "Musculación"... } del segundo objeto dentro del array "instalaciones".
6. Sobra la coma final (trailing comma) después del segundo objeto { "zona": "Cardio", "planta": 2 } del array.
7. "nutricionista": "null" -> Error de tipo: debe usarse el literal null sin comillas para representar que aún no tiene nutricionista.

=== TAREA 5: COMPARATIVA XPATH VS JSON Y NAVEGACIÓN ===
(a) Obtener las series de "Sentadilla" en la rutina RUT002:
- En XML usando XPath (filtrando por atributo @id y elemento hijo nombre):
  //rutina[@id='RUT002']//ejercicio[nombre='Sentadilla']/series
- En JSON usando ruta por índices (recordando que los arrays empiezan en 0, por lo que RUT002 es rutinas[1] y Sentadilla es ejercicios[0]):
  gimnasio.rutinas[1].ejercicios[0].series

(b) Ruta JSON a las kcalQuemadas de la segunda sesión del primer socio (SOC01):
  gimnasio.socios[0].sesiones[1].kcalQuemadas

(c) Por qué usar [] en materialNecesario (RUT003) frente a null en fichaMedica (SOC02):
- "materialNecesario": [] es una lista/colección de elementos que en esa rutina tiene 0 elementos; usar un array vacío mantiene el mismo tipo de dato Array en todas las rutinas.
- "fichaMedica": null representa un objeto único que el socio SOC02 aún no ha entregado; usar null indica claramente la ausencia de ese bloque de datos.
